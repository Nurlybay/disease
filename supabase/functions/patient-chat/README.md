# Автоматический диалог без тестового пароля

Фронтенд создаёт анонимную сессию Supabase Auth при первом вопросе. Каждый
ноутбук/браузер получает отдельного гостя. Провайдерский ключ остаётся в Secrets.
Функция проверяет JWT через Auth и резервирует квоту в PostgreSQL до обращения
к NeuralDeep. Если проверка или база недоступна, запрос провайдеру не отправляется.

## Настройка в Dashboard

1. Откройте SQL Editor проекта и выполните целиком
   `supabase/migrations/202609070001_guest_chat_limits.sql`.
2. В Authentication → Sign In / Providers включите **Allow anonymous sign-ins**.
   Вход без email/пароля описан в [документации Supabase](https://supabase.com/docs/guides/auth/auth-anonymous).
   Текущий клиент не передаёт CAPTCHA; если проект её требует, сначала добавьте
   виджет и captchaToken в запрос регистрации. Встроенный лимит регистрации
   гостей по IP может ограничить одновременное подключение группы из одной сети.
3. В Edge Functions → patient-chat → Code замените код целиком содержимым
   соседнего `index.ts` и нажмите Deploy. Это один самостоятельный файл.
4. Для этой функции отключите **Verify JWT with legacy secret**. Проверка
   пользователя остаётся внутри функции через `/auth/v1/user`; один публичный
   anon key не даёт доступа к диалогу. Это соответствует `supabase/config.toml`.
5. В Edge Functions → Secrets оставьте `NEURALDEEP_API_KEY` с настоящим ключом
   и `NEURALDEEP_MODEL` с точным ID модели (например, предоставленный вами
   `qwen3.8-27b`, если доступен в кабинете). `SUPABASE_URL` и
   `SUPABASE_ANON_KEY` предоставляются средой. Старый `PATIENT_CHAT_ACCESS_CODE`
   больше не используется. Не вставляйте ключ NeuralDeep в сайт.
6. Опубликуйте обновлённую папку `site` и откройте приём. Напишите вопрос:
   «Сколько дней у вас температура?». Сайт сам создаст гостя и отправит запрос.
   Обычный Dashboard Test с anon JWT и старым x-patient-access теперь не подходит:
   нужен JWT реального гостя, поэтому проверяйте через сайт.

## Что изменилось

Все двенадцать встроенных пациентов поддерживают свободные текстовые ответы.
Распознанные вопросы о симптомах и нераспознанные фразы идут к ИИ. Осмотр,
измерения, назначения и лечение остаются сценарными действиями. Неоднозначные
действия требуют выбора. Пользовательские случаи пока используют сценарные ответы.
ИИ не получает ключ оценки, диагноз или результаты обследований. История
ограничена 20 репликами и считается недоверенным контекстом; факты берутся
из серверной карточки. При изменении сценария запустите `node tools/build-patient-chat-cards.js`
и обновите функцию. Карточки всех двенадцати пациентов содержат тему каждого факта.
Общие правила требуют отвечать на конкретный вопрос, не переносить сроки и числа
между симптомами, не путать отсутствие сведений с отрицанием и не придумывать
причину незнания. Понятный вопрос с неизвестным ответом не требует повторения;
неоднозначный предмет вопроса требует уточнения. Специальных правил для одного
пациента или симптома нет. Подсказка модели не гарантирует отсутствие выдумок: клинические ответы
нужно проверить вручную. Голосовая генерация и автоматическая оценка ИИ-расспроса
не реализованы. Перезапуск приёма очищает диалог, но сохраняет гостевую сессию.

## Лимиты

По умолчанию: 6 запросов за календарную минуту и 30 за сутки на гостя,
200 за сутки и 2000 суммарно на проект. Сутки считаются по UTC. Квота резервируется
перед запросом: ошибки провайдера тоже расходуют её. Это лимиты числа запросов,
не точный бюджет в долларах. Удаление localStorage создаёт нового гостя, но не
обнуляет общие лимиты. JWT не позволяет читать или менять таблицы квот.
Гость может самостоятельно вызвать RPC и потратить свою квоту без диалога;
это не позволяет превысить общий лимит вызовов провайдера. Для масштабирования
понадобятся защита регистрации от ботов и политика очистки старых auth.users.

Посмотреть расход в SQL Editor:

```sql
select * from patient_chat_private.budget;
```

Остановить платные запросы, сохранив сайт и сценарные действия:

```sql
update patient_chat_private.budget set enabled = false where id = 1;
```

Возобновление/повышение лимита делайте осознанно через эту таблицу.
Лимит 2000 не сбрасывается автоматически и не сбрасывается повторным запуском миграции.

## Проверки и ошибки

`node tools/test-patient-chat.js` проверяет сервер с подменёнными Auth/RPC/NeuralDeep.
`node tools/test-patient-chat-client.js` проверяет регистрацию, сохранение и обновление
сессии, историю, отмену, ошибки и отсутствие парольного заголовка.
Миграция дополнительно проверена на отдельной временной PostgreSQL:
12 конкурентных вызовов допускают ровно 6; права и суточные/общие лимиты работают.
Реальный гостевой вызов NeuralDeep требует настройки проекта выше.

- `guest_disabled`: анонимный вход выключен.
- `guest_expired`: сессия недействительна, повторите вопрос.
- `quota_unavailable`: миграция не применена либо RPC недоступен.
- `guest_rate_limit`, `guest_daily_limit`, `global_daily_limit`, `total_limit`: квота.
- `server_not_configured`: отсутствуют обязательные настройки функции.
- `provider_timeout`, `provider_network_error`: тайм-аут/сеть провайдера.

Ключи и полные тела ошибок провайдера в ответы и логи не выводятся.

## Провайдер и длинные диалоги

По умолчанию остаётся NeuralDeep. Для OpenRouter добавьте серверные Secrets:
`PATIENT_CHAT_PROVIDER=openrouter`, `OPENROUTER_API_KEY` (ключ из кабинета),
`OPENROUTER_MODEL` (точный ID выбранной модели). Не помещайте ключ в сайт или Git.
Для возврата задайте `PATIENT_CHAT_PROVIDER=neuraldeep`. Переключение не меняет
карточки, языки и квоты. OpenRouter получает `provider.sort=latency`, разрешённые
резервные провайдеры и `reasoning.enabled=false`. Скорость требует живого замера.

Принимаются до 20 сообщений истории по 1000 символов. Лимит тела 96 КБ
покрывает Unicode в разрешённых полях; прежде 24 КБ не вмещали длинные диалоги.
Модель получает не более 12 последних сообщений и 6000 символов истории,
старые пары удаляются целиком. Карточка пациента всегда остаётся в контексте.
Тест клиента проверяет 35 последовательных вопросов; серверный — длинную
кириллическую историю и оба провайдера с имитацией API. Это не нагрузочный тест
провайдера и не изменение существующих денежных/суточных квот.

## Озвучка свободных ответов

Клиент передаёт `withAudio:true`. При OpenRouter для RU/EN сервер озвучивает
только свой проверенный текст ответа через `minimax/speech-2.8-turbo`
(`/audio/speech`), выбирая голос по полу из карточки. MP3 передаётся в JSON
как base64; ключ остаётся в Secrets. Это дополнительный платный TTS-запрос
в рамках того же квотируемого вопроса. Ожидание TTS ограничено 15 секундами;
при сбое сохраняется текст. KK пока использует прежнюю браузерную озвучку.
https://openrouter.ai/docs/guides/overview/multimodal/tts

Источники кашля перенесены в раздел преподавателя. Выделенный пользователем
блок под портретом скрыт, включая технический статус браузерной озвучки.
