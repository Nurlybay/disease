# Виртуальный приём — тренажёр клинического мышления

Интерактивный сайт: пациент приходит на приём, врач (пользователь) собирает
анамнез, аускультирует лёгкие, осматривает пациента, назначает исследования и
лечение, ставит диагноз и получает разбор с оценкой.

Основная нагрузка — **звуковая**: жалоба и все ответы пациента озвучены,
аускультация — реальная аудиозапись с волновой формой на canvas.

Разобранный случай: **бронхоэктатическая болезнь**.

Ничего платного и никакой сети: ни моделей, ни API, ни `fetch()`. Всё, включая
разбор свободного текста, считается локально в браузере.

---

## Две ветки — два тренажёра

| Ветка | Вариант | Что проверяет |
|---|---|---|
| `main` | **свободный приём** | знание и алгоритм: врач сам решает, что делать и в каком порядке |
| `guided` | **пошаговый осмотр** | узнавание: 6 фиксированных этапов, готовые вопросы кнопками |

```
git switch main      # свободный приём
git switch guided    # пошаговый осмотр
```

Оба варианта работают из `file://` и делят общие медиафайлы, озвучку и
инструменты в `tools/`.

---

## Как запустить

Вариант 1 — просто открыть файл:

```
open site/index.html
```

Работает и с `file://`: в коде нет ES-модулей, `fetch()` и Web Audio —
всё грузится обычными `<script>`.

Вариант 2 — локальный сервер (надёжнее для видео в некоторых браузерах):

```
cd site && python3 -m http.server 8777
# затем http://localhost:8777/index.html
```

**Включите звук, лучше наушники.** Дыхательные шумы лежат в 100–1000 Гц —
динамики ноутбука срезают половину полосы.

# Свободный приём (ветка `main`)

## Идея

Экран стартует пустым. Неизвестно **ничего**: ни имени пациента, ни возраста,
ни температуры, ни пульса. Пациент произносит одну вступительную жалобу — и
дальше молчит, пока его не спросят.

Никаких этапов, никакого списка готовых вопросов, никакой подсказки «что
дальше». Врач печатает своими словами:

```
как вас зовут
измерить сатурацию
давно кашляете
послушать лёгкие
осмотреть пальцы
посев мокроты
постуральный дренаж
диагноз бронхоэктатическая болезнь
```

Порядок выбирает врач. Можно начать с КТ и закончить жалобами — программа не
мешает, но запоминает и разбирает это в конце. Именно предъявленный порядок и
есть проверяемый алгоритм.

## Ввод: строка + кнопки категорий

Шесть кнопок над строкой ввода задают только **тип** действия и фокусируют
строку. Они не подсказывают, что именно спросить или назначить в этом случае:

| Кнопка | Категория | Пример ввода |
|---|---|---|
| Спросить | `ask` | «давно кашляете», «мокрота какая» |
| Измерить | `measure` | «измерить сатурацию», «взвесить» |
| Осмотреть | `exam` | «послушать лёгкие», «осмотреть пальцы» |
| Назначить | `order` | «посев мокроты», «кт грудной клетки» |
| Лечение | `treat` | «постуральный дренаж», «назначить антибиотик» |
| Диагноз | `dx` | «диагноз бронхоэктазы» |

Кнопка не обязательна. Категория обычно вычисляется из глагола: «измерить…»,
«послушать…», «назначить…», «спросить про…». Кнопка нужна, когда врач вводит
одно слово, которое годится сразу в две категории («температура» — спросить
или измерить?).

## Что заполняется по ходу приёма

* **Паспортная часть** — 8 полей `<dl>`, каждое сначала курсивом «не спрошено».
* **Показатели** — 6 плиток в состоянии «— не измерено».
* **Карта осмотра** — заметки, которые врач набирает сам.
* **Протокол приёма** — журнал всех действий по порядку: номер, время,
  категория, что сделано, что получено. Патологические находки помечены,
  повторы приглушены, нераспознанный ввод подсвечен.

Панель аускультации раскрывается как результат действия «послушать лёгкие», а
не как отдельный этап.

## Разбор в конце

Кнопка «Завершить приём» (или `?finish=1`) открывает разбор:

1. **Хронология приёма** — весь список действий по порядку с временем.
2. **Ошибки и пропуски** — 11 групп: не собраны паспортные данные · не
   измерено · не заданы важные вопросы (каждый с пояснением, зачем он нужен) ·
   не выявлены патологии · не назначено (обследование) · не назначено
   (лечение) · назначено зря · назначено ошибочно · вопросы, которых пациент
   не понял · замечания по алгоритму · и «всё чисто», если пропусков нет.
3. **Оценка** — 8 плиток:

```
25 % расспрос ·  5 % паспортная часть · 10 % показатели · 20 % физикальный осмотр
15 % обследование · 10 % лечение · 10 % диагноз ·  5 % алгоритм
```

4. **Ловушка случая** и разбор всех 6 альтернативных диагнозов.

Замечания по алгоритму — 13 правил на *порядок*, например: осмотр начат до
расспроса · исследования назначены до физикального осмотра · КТ без рентгена ·
диагноз до аускультации · аускультация без просьбы дышать глубоко · антибиотик
без посева · кровохарканье без КУБ.

Оценка алгоритма — **доля соблюдённых правил среди тех, что были в игре**.
У правила есть предпосылка (`when`): «КТ без рентгена» ничего не говорит о
враче, который КТ не назначал, и в знаменатель не попадает. Плитка показывает,
сколько правил учтено. Иначе бездействие получало бы высокий балл за алгоритм
просто потому, что нарушать было нечего: приём «диагноз ОРВИ и всё» давал
25 %, теперь даёт 0 % при 5 правилах в игре.

## Данные случая

`site/cases/bronchiectasis.js` — один `window.CASES.push({...})`, **82
намерения**. Каждая запись несёт свой триггер распознавания рядом с ответом,
поэтому данные и распознавание не могут разъехаться:

```js
{ id: 'o.sput_culture', cat: 'order', w: 2, role: 'need',
  label: 'Посев мокроты с чувствительностью',
  need: [['мокрот'], ['посев','культур','чувствитель']],
  no: ['куб','микроскоп'],
  result: '…' }
```

Состав: `passport` 8 · `questions` 20 · `vitals` 6 · `exams` 12 ·
`auscultation` 6 точек · `orders` 18 (нужные, полезные и бесполезные —
чтобы измерять избыточные назначения) · `treatment` 12 (нужное, полезное и
прямо вредное: системные стероиды, подавление продуктивного кашля) ·
`diagnosis` 6 вариантов · `algorithm` 13 правил порядка.

## Сопоставитель свободного текста

`site/nlu.js`, ~300 строк, без ИИ и без сети. Конвейер: нормализация →
токенизация → жёсткая маршрутизация по глаголу → счёт групп → порог.

**Схема намерения.** `need` — массив групп основ; группа закрыта, если совпала
любая её основа. Кандидат — только намерение, у которого закрыты **все**
группы и не совпало ничего из `no`. `w` — специфичность.

**Совпадение основы без стеммера.** Основа длиной ≥ 4 ищется подстрокой
(`кашл` ловит «кашель», «кашляете», «кашлял»), длиной ≤ 3 — точным
равенством (`кт`, `оак`, `экг`). Стеммер из плана не понадобился: подстрока
уже поглощает русское словоизменение, а отсечение окончаний добавило бы риск
пересечения основ.

**Маршрутизация — фильтр, а не подсказка.** Глагол действия определяет
категорию однозначно и отбрасывает чужие кандидаты **до** подсчёта. Нажатая
кнопка категории делает то же самое.

**Порог.** `score = закрытые группы + w`, вопросительная форма даёт `+2`
расспросу. Принять, если кандидат один, или разрыв ≥ 2, или внутри одной
категории у лучшего выше `w`. Иначе — до 3 кнопок уточнения под строкой ввода
(выбор кнопки не штрафуется в разборе).

**Опечатки — узкая аварийная ступень.** Дамерау—Левенштейн включается только
когда кандидатов ноль, и принимается только если исправление даёт ровно
одного кандидата. Иначе «не понял». Матчер, который угадывает за студента,
завышает оценку.

**Отрицание — минимально.** «не надо назначать КТ» → действие не выполняется,
в журнал пишется отказ. В вопросах отрицание игнорируется: «курите» и «не
курите» — один и тот же вопрос.

## Тесты сопоставителя

```
open tools/test-nlu.html          # в браузере, таблица с зелёными строками
node tools/run-nlu-tests.js       # то же в терминале, код возврата ≠ 0 при провале
```

76 пар «ввод → ожидаемый результат»: принятые намерения, ожидаемые уточнения,
нераспознанное, отказ, исправленная опечатка и перекрытие кнопкой категории.
Заголовок вкладки показывает итог. Node-обёртка читает таблицу из того же
html, поэтому два прогона не могут расходиться.

**Прогонять при каждом изменении `nlu.js` или триггеров в файле случая** —
коллизии основ ловятся только так. Три штуки уже поймались: `снимк` не ловит
«снимок» (подстрока идёт в другую сторону), а `осмотр грудн` с пробелом
никогда не совпадёт с одиночным токеном.

## Отладочные параметры URL

| Параметр | Действие |
|---|---|
| `?demo=1` | «идеальный» приём: все вопросы, измерения, осмотры, назначения |
| `?dx=ari` | сразу подставить диагноз (id из `case.diagnosis.options`) |
| `?finish=1` | сразу открыть разбор |

Примеры: `index.html?demo=1&finish=1` — разбор безупречного приёма;
`index.html?dx=ari&finish=1` — разбор, когда врач ничего не сделал и назвал ОРВИ.

# Пошаговый осмотр (ветка `guided`)

| Этап | Что делает пользователь |
|---|---|
| 1. Жалобы | слушает вступительную реплику пациента |
| 2. Анамнез | задаёт до 10 вопросов кнопками, каждый ответ озвучен |
| 3. Аускультация | 6 полей на схеме грудной клетки, прослушивание, проба с кашлем |
| 4. Зев | видео переключается на осмотр зева |
| 5. Исследования | назначает из 5 доступных, видит результаты |
| 6. Диагноз | выбирает 1 из 6 вариантов |
| 7. Разбор | оценка в % + список пропущенного |

Оценка: `32 % анамнез · 18 % охват точек · 14 % патология · 4 % зев ·
4 % кашель · 8 % исследования · 20 % диагноз`.

URL: `?demo=1`, `?stage=…` (`intake`, `history`, `auscult`, `throat`,
`workup`, `dx`, `debrief`), `?dx=…`.

## Клиника случая

Ловушка: пациент открывает приём словами «у меня появился небольшой кашель»,
хотя кашлю больше восьми месяцев и мокроты около 100 мл в сутки, в детстве —
тяжёлая пневмония, дважды кровохарканье, не курит. Без расспроса случай
выглядит как ОРВИ.

Аускультация «вид со спины»: **правое лёгкое пациента — слева от вас**.
Хрипы в трёх полях: R-середина, R-низ, L-низ.

Ключевые находки, которые обязан добыть врач: продуктивный кашель большого
объёма с гнойной мокротой · пневмония в детстве как причина · кровохарканье ·
некурящий (значит, не ХОБЛ) · влажные хрипы в базальных отделах и правой
средней доле · пальцы Гиппократа · на КТ отношение диаметра бронха к артерии
больше 1.

## Как добавить свой случай

1. Скопируйте `site/cases/bronchiectasis.js`, поменяйте данные.
2. Подключите в `index.html`: `<script src="cases/ваш-файл.js"></script>`.
3. Озвучьте ответы: добавьте строки в `tools/make-voice.sh` и запустите его.
   Имена файлов должны совпадать с полями `audio` — иначе пациент промолчит.
4. Добавьте пары в `tools/test-nlu.html` и прогоните таблицу: новые основы
   почти всегда сталкиваются с уже существующими.
5. Если меняете аудио аускультации — обновите `TARGETS` в
   `tools/make-waveforms.py` и запустите скрипт.

Координаты точек аускультации (`x`, `y` в файле случая) заданы в системе
координат SVG `viewBox="0 0 300 380"` из `index.html` — при правке схемы
их нужно править вместе с ней.

## Откуда взялись медиафайлы

Исходники лежат в `sources/`: два видео Hailuo и `Crackles-Bronchiectasis.mp3`.

**Видео.** Обработаны ffmpeg:

* `patient-idle.mp4` — кроп убирает водяной знак MINIMAX/Hailuo (обрезка
  правого края), затем «палиндром» (`split` → `reverse` → `concat`), чтобы
  цикл шёл без рывка на стыке.
* `patient-throat.mp4` — снят только чёрный паддинг по бокам; исходник сам
  наезжает на ротоглотку во второй половине клипа.

**Голос.** `tools/make-voice.sh`. В macOS есть единственный русский голос —
женский `Milena`, поэтому он сдвинут в мужской диапазон:
`asetrate=44100*0.84` + компенсация темпа `atempo=1.190476`, затем полосовая
фильтрация и `loudnorm`.

**Звуки лёгких — важное уточнение:**

* `lung-crackles.mp3` — **реальная запись** пользователя
  (`Crackles-Bronchiectasis.mp3`), только нормализована по громкости.
* `lung-normal.mp3` — **синтезирована**: розовый шум → `bandpass` →
  огибающая дыхания через `volume=...:eval=frame`. Записи нормального
  дыхания среди исходников не было, а без «нормы» тренажёр теряет главное:
  задачу отличить патологию от нормы на слух. Как эталон везикулярного
  дыхания для обучения её использовать нельзя.

**Проба с кашлем** тоже честная в своих ограничениях: записи «после
покашливания» не существует, поэтому действие не подделывает изменившийся
звук — оно добавляет клиническую заметку об изменчивости хрипов и
воспроизводит ту же запись.

**Волновая форма.** Web Audio API на `file://` не может анализировать
локальный файл (`createMediaElementSource` отдаёт нули), поэтому пики
считаются заранее в `tools/make-waveforms.py` (RMS, 420 столбиков) и
кладутся в `waveforms.js` рядом с `.json` — `<script>` работает там, где
`fetch()` запрещён.

## Ограничения

Это учебный тренажёр, не медицинское изделие и не диагностический
инструмент. Данные пациента вымышлены, `lung-normal.mp3` синтетический.
Сопоставитель свободного текста понимает только те формулировки, основы
которых заложены в файл случая: он проверяет знание терминов и порядка
действий, а не владение языком.
