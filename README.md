# Виртуальный приём — тренажёр клинического мышления

Интерактивный сайт: пациент приходит на приём, врач (пользователь) собирает
анамнез, аускультирует лёгкие, осматривает пациента, назначает исследования и
лечение, ставит диагноз и получает разбор с оценкой.

Основная нагрузка — **звуковая**: жалоба и все ответы пациента озвучены,
аускультация — реальная аудиозапись с волновой формой на canvas.

Вход — витрина `site/index.html`: сверху две карточки — **студенту**
(случайный пациент) и **преподавателю** (методичка, критерии, журнал и
конструктор). Ниже — пронумерованный выбор конкретного случая, включая
свои из конструктора, и импорт файла случая.

Случаев четыре — по одному персонажу на болезнь, студенту при загрузке
достаётся **случайный** (отладка: `priem.html?char=имя-файла-без-.js`):

| Персонаж | Болезнь | Файл |
|---|---|---|
| Абенов Мурат, 34 | бронхоэктатическая болезнь | `site/characters/bronchiectasis-abenov.js` |
| Есжанова Айгерим, 24 | бронхиальная астма | `site/characters/asthma-eszhanova.js` |
| Омаров Даулет, 21 | муковисцидоз | `site/characters/cf-omarov.js` |
| Байжанов Серик, 67 | ХСН, застой в лёгких | `site/characters/chf-baizhanov.js` |

Ничего платного и никакой сети: ни моделей, ни API, ни `fetch()`. Всё, включая
разбор свободного текста, считается локально в браузере. Единственное
исключение — необязательный локальный ЛЛМ-прокси для нераспознанных фраз
(см. «ЛЛМ-фолбэк понимания»): без него сайт работает точно так же.

---

## Две ветки — два тренажёра

| Ветка | Вариант | Что проверяет |
|---|---|---|
| `main` | **свободный приём** | знание и алгоритм: врач сам решает, что делать и в каком порядке |
| `guided` | **пошаговый осмотр** | узнавание: 6 фиксированных этапов, готовые вопросы кнопками |

```
git switch main      # свободный приём
git switch guided    # пошаговый осмотр
```

Оба варианта работают из `file://` и делят общие медиафайлы, озвучку и
инструменты в `tools/`.

---

## Как запустить

Вариант 1 — просто открыть файл:

```
open site/index.html    # витрина; тренажёр — priem.html
```

Работает и с `file://`: в коде нет ES-модулей, `fetch()` и Web Audio —
всё грузится обычными `<script>`.

Вариант 2 — локальный сервер (надёжнее для видео в некоторых браузерах):

```
cd site && python3 -m http.server 8777
# затем http://localhost:8777/index.html
```

**Включите звук, лучше наушники.** Дыхательные шумы лежат в 100–1000 Гц —
динамики ноутбука срезают половину полосы.

# Свободный приём (ветка `main`)

## Идея

Экран стартует пустым. Неизвестно **ничего**: ни имени пациента, ни возраста,
ни температуры, ни пульса. Пациент произносит одну вступительную жалобу — и
дальше молчит, пока его не спросят.

Никаких этапов, никакого списка готовых вопросов, никакой подсказки «что
дальше». Врач печатает своими словами:

```
как вас зовут
измерить сатурацию
давно кашляете
послушать лёгкие
осмотреть пальцы
посев мокроты
постуральный дренаж
диагноз бронхоэктатическая болезнь
```

Порядок выбирает врач. Можно начать с КТ и закончить жалобами — программа не
мешает, но запоминает и разбирает это в конце. Именно предъявленный порядок и
есть проверяемый алгоритм.

## Ввод: строка + кнопки категорий

Шесть кнопок над строкой ввода задают только **тип** действия и фокусируют
строку. Они не подсказывают, что именно спросить или назначить в этом случае:

| Кнопка | Категория | Пример ввода |
|---|---|---|
| Спросить | `ask` | «давно кашляете», «мокрота какая» |
| Измерить | `measure` | «измерить сатурацию», «взвесить» |
| Осмотреть | `exam` | «послушать лёгкие», «осмотреть пальцы» |
| Назначить | `order` | «посев мокроты», «кт грудной клетки» |
| Лечение | `treat` | «постуральный дренаж», «назначить антибиотик» |
| Диагноз | `dx` | «диагноз бронхоэктазы» |

Кнопка не обязательна. Категория обычно вычисляется из глагола: «измерить…»,
«послушать…», «назначить…», «спросить про…». Кнопка нужна, когда врач вводит
одно слово, которое годится сразу в две категории («температура» — спросить
или измерить?).

У «Измерить» и «Назначить» есть второй ряд — подгруппы. Показатели названы
прямо (температура, пульс, ЧДД, АД, SpO₂, рост и вес) и выполняются кликом:
их шесть плиток и так видно на экране с самого старта, кнопки не выдают
ничего нового. Подгруппы назначений остаются родовыми («Анализы»,
«Инструментальные») — они сужают подсказку, но что именно назначить, врач
по-прежнему пишет сам.

## Что заполняется по ходу приёма

* **Паспортная часть** — 8 полей `<dl>`, каждое сначала курсивом «не спрошено».
* **Показатели** — 6 плиток в состоянии «— не измерено».
* **Карта осмотра** — заметки, которые врач набирает сам.
* **Протокол приёма** — журнал всех действий по порядку: номер, время,
  категория, что сделано, что получено. Патологические находки помечены,
  повторы приглушены, нераспознанный ввод подсвечен.

Панель аускультации раскрывается как результат действия «послушать лёгкие», а
не как отдельный этап.

## Разбор в конце

Кнопка «Завершить приём» (или `?finish=1`) открывает разбор:

1. **Хронология приёма** — весь список действий по порядку с временем.
2. **Ошибки и пропуски** — 11 групп: не собраны паспортные данные · не
   измерено · не заданы важные вопросы (каждый с пояснением, зачем он нужен) ·
   не выявлены патологии · не назначено (обследование) · не назначено
   (лечение) · назначено зря · назначено ошибочно · вопросы, которых пациент
   не понял · замечания по алгоритму · и «всё чисто», если пропусков нет.
3. **Оценка** — 8 плиток:

```
25 % расспрос ·  5 % паспортная часть · 10 % показатели · 20 % физикальный осмотр
15 % обследование · 10 % лечение · 10 % диагноз ·  5 % алгоритм
```

4. **Ловушка случая** и разбор всех 6 альтернативных диагнозов.
5. **Отправить результат преподавателю** — ФИО и группа, затем «Скопировать
   код» или «Скачать файл». Код `VP1.…` — это сам протокол приёма без
   готового балла; оценка пересчитывается на стороне преподавателя
   (см. «Раздел преподавателя»).

Замечания по алгоритму — 13 правил на *порядок*, например: осмотр начат до
расспроса · исследования назначены до физикального осмотра · КТ без рентгена ·
диагноз до аускультации · аускультация без просьбы дышать глубоко · антибиотик
без посева · кровохарканье без КУБ.

Оценка алгоритма — **доля соблюдённых правил среди тех, что были в игре**.
У правила есть предпосылка (`when`): «КТ без рентгена» ничего не говорит о
враче, который КТ не назначал, и в знаменатель не попадает. Плитка показывает,
сколько правил учтено. Иначе бездействие получало бы высокий балл за алгоритм
просто потому, что нарушать было нечего: приём «диагноз ОРВИ и всё» давал
25 %, теперь даёт 0 % при 5 правилах в игре.

## Данные случая

Каждый персонаж — самодостаточный файл в `site/characters/` с одним
`window.CASES.push({...})` (у Абенова, например, **82 намерения**);
`characters/manifest.js` — реестр, `characters/loader.js` подключает
случайный файл и лишь затем `app.js`, так что приложение всегда видит ровно
один случай. Каждая запись несёт свой триггер распознавания рядом с ответом,
поэтому данные и распознавание не могут разъехаться:

```js
{ id: 'o.sput_culture', cat: 'order', w: 2, role: 'need',
  label: 'Посев мокроты с чувствительностью',
  need: [['мокрот'], ['посев','культур','чувствитель']],
  no: ['куб','микроскоп'],
  result: '…' }
```

Состав: `passport` 8 · `questions` 20 · `vitals` 6 · `exams` 12 ·
`auscultation` 6 точек · `orders` 18 (нужные, полезные и бесполезные —
чтобы измерять избыточные назначения) · `treatment` 12 (нужное, полезное и
прямо вредное: системные стероиды, подавление продуктивного кашля) ·
`diagnosis` 6 вариантов · `algorithm` 13 правил порядка.

## Сопоставитель свободного текста

`site/nlu.js`, ~300 строк, без ИИ и без сети. Конвейер: нормализация →
токенизация → жёсткая маршрутизация по глаголу → счёт групп → порог.

**Схема намерения.** `need` — массив групп основ; группа закрыта, если совпала
любая её основа. Кандидат — только намерение, у которого закрыты **все**
группы и не совпало ничего из `no`. `w` — специфичность.

**Совпадение основы без стеммера.** Основа длиной ≥ 4 ищется подстрокой
(`кашл` ловит «кашель», «кашляете», «кашлял»), длиной ≤ 3 — точным
равенством (`кт`, `оак`, `экг`). Стеммер из плана не понадобился: подстрока
уже поглощает русское словоизменение, а отсечение окончаний добавило бы риск
пересечения основ.

**Маршрутизация — фильтр, а не подсказка.** Глагол действия определяет
категорию однозначно и отбрасывает чужие кандидаты **до** подсчёта. Нажатая
кнопка категории делает то же самое.

**Порог.** `score = закрытые группы + w`, вопросительная форма даёт `+2`
расспросу. Принять, если кандидат один, или разрыв ≥ 2, или внутри одной
категории у лучшего выше `w`. Иначе — до 3 кнопок уточнения под строкой ввода
(выбор кнопки не штрафуется в разборе).

**Опечатки — узкая аварийная ступень.** Дамерау—Левенштейн включается только
когда кандидатов ноль, и принимается только если исправление даёт ровно
одного кандидата. Иначе «не понял». Матчер, который угадывает за студента,
завышает оценку.

**Отрицание — минимально.** «не надо назначать КТ» → действие не выполняется,
в журнал пишется отказ. В вопросах отрицание игнорируется: «курите» и «не
курите» — один и тот же вопрос.

## Необязательный ЛЛМ-фолбэк понимания

`tools/nlu-proxy.py` — локальный прокси, который сайт спрашивает **только
когда офлайновый сопоставитель сдался**. Модель не отвечает за пациента, не
сочиняет реплик и не ставит оценок: она выбирает id намерения из каталога,
который страница прислала вместе с фразой, — дальше всё идёт обычным
конвейером (озвученный заранее ответ, детерминированный разбор). В журнале
такое действие помечено «понято как …».

```
export LLM_API_KEY=sk-...        # ключ только в переменной окружения
python3 tools/nlu-proxy.py       # http://127.0.0.1:8790/match
```

Без запущенного прокси сайт работает ровно как раньше: запрос на 127.0.0.1
мгновенно падает, врач видит обычное «не понял вопроса». Ключа в репозитории
нет и не должно быть. Прокси — единственное место, где появляется сеть и
модель; сам сайт по-прежнему офлайн и бесплатен.

## Тесты сопоставителя

```
open tools/test-nlu.html          # в браузере, таблица с зелёными строками
node tools/run-nlu-tests.js       # то же в терминале, код возврата ≠ 0 при провале
```

80 пар «ввод → ожидаемый результат»: принятые намерения, ожидаемые уточнения,
нераспознанное, отказ, исправленная опечатка и перекрытие кнопкой категории.
Заголовок вкладки показывает итог. Node-обёртка читает таблицу из того же
html, поэтому два прогона не могут расходиться.

**Прогонять при каждом изменении `nlu.js` или триггеров в файле случая** —
коллизии основ ловятся только так. Три штуки уже поймались: `снимк` не ловит
«снимок» (подстрока идёт в другую сторону), а `осмотр грудн` с пробелом
никогда не совпадёт с одиночным токеном.

## Отладочные параметры URL

| Параметр | Действие |
|---|---|
| `?char=cf-omarov` | конкретный персонаж вместо случайного (имя файла без `.js`) |
| `?demo=1` | «идеальный» приём: все вопросы, измерения, осмотры, назначения |
| `?dx=ari` | сразу подставить диагноз (id из `case.diagnosis.options`) |
| `?finish=1` | сразу открыть разбор |

Все параметры — на `priem.html` (витрина `index.html` прокидывает `?char=`
и остальное дальше сама).

Примеры: `priem.html?demo=1&finish=1` — разбор безупречного приёма;
`priem.html?dx=ari&finish=1` — разбор, когда врач ничего не сделал и назвал ОРВИ.

# Раздел преподавателя (ветка `main`)

`teacher.html` — без пароля, но с честным предупреждением на витрине: здесь
все ответы случаев и результаты студентов, студентам здесь делать нечего.
Четыре вкладки: методичка, журнал, критерии и конструктор случаев.

## Методичка по случаям

Рендерится целиком из файлов персонажей — отдельной методички не существует
и разъехаться с тренажёром она не может. Для каждого случая: ловушка,
вступительная жалоба, паспортная часть с пояснениями «зачем спрашивать»,
все вопросы с ответами пациента и кнопками прослушивания (есть «Прослушать
все ответы» подряд), показатели с методикой измерения, физикальный осмотр,
карта аускультации с уже раскрашенными патологическими точками (клик по
точке — звук), обследование и лечение по ролям (обязательно / полезно /
зря / вредно), все 6 вариантов диагноза с разбором, правила алгоритма,
ключевые находки и тактика.

Новый персонаж в `manifest.js` появляется в методичке автоматически.

## Ссылки для аудитории

В шапке каждого случая: «Запустить случай» → `priem.html?char=<id>`,
«Идеальный приём» → `?char=<id>&demo=1`, «Разбор идеального приёма» →
`?char=<id>&demo=1&finish=1` — удобно показывать на проекторе.

## Журнал результатов

Студент в разборе нажимает «Отправить результат преподавателю», вводит ФИО
и группу, получает код `VP1.<base64>` (или файл `.txt` с тем же кодом) и
пересылает его любым способом. Преподаватель вставляет коды в журнал —
по одному в строке или файлами.

В коде — сам протокол приёма (что и в каком порядке сделано, длительность,
выставленный диагноз, нераспознанные фразы), но **не балл**: оценка всегда
пересчитывается из протокола на стороне преподавателя, подделать итог
правкой кода нельзя (можно только испортить).

Журнал показывает таблицу (итог, диагноз, действий, длительность), по клику
— мини-разбор: 8 плиток, нарушения алгоритма, пропуски, хронология. Сводка
по всем добавленным: средние, топ-5 частых пропусков, топ нарушений,
распределение диагнозов. Экспорт — CSV (`;`, BOM для Excel), там же
исходный код для переноса на другую машину. Хранение — `localStorage`
(если браузер его блокирует на `file://`, журнал живёт до перезагрузки —
тогда выручает CSV).

**Это не прокторинг.** Код честно фиксирует то, что происходило в браузере
студента, но не подтверждает личность и не мешает консультироваться с
одногруппниками. Подходит для семинара и самопроверки, не для экзамена.

## Критерии оценки

Те же 8 плиток с весами из `Score.WEIGHTS` (единственный источник правды —
методичка и разбор показывают одно и то же), штрафы за лишние назначения,
формула аускультации и логика «доля соблюдённых правил среди правил в игре».

## Конструктор случаев

Четвёртая вкладка — редактор своих случаев без правки кода: болезнь,
паспортная часть, жалобы и ответы пациента, показатели, осмотр, назначения,
лечение, дифференциальная диагностика, правила алгоритма (по умолчанию —
все девять включены), аускультация по 6 точкам и тексты разбора. Картинки
(result-изображения) прикрепляются к осмотру, назначениям и лечению —
сохраняются в локальном хранилище как data-uri.

Заготовка уже заполнена: паспортные поля (ФИО, возраст) и все шесть
показателей (температура, пульс, ЧДД, сатурация, АД, рост/вес) получают
корни распознавания от встроенных случаев, чтобы фиксированные кнопки
«Измерить» работали из коробки. Звуки лёгких берутся из общей библиотеки
`media/lungs/` — норма и четыре патологии (хрипы-бронхоэктазы, хрипы-муковисцидоз,
хрипы-застой, астма свистящая), на каждую из 6 точек назначается одна из них
или норма. Озвучки в своих случаях нет: реплики пациента и кнопки-озвучки
ограничены субтитрами — в остальном приём идёт и разбирается тем же кодом.

Хранение — `localStorage` (`vp.custom.cases.v1`); случай остаётся на том же
браузере, где его сделали. Поддержан экспорт/импорт файла `.js` в размеченном
формате (см. подробно `site/characters/README.md`), что позволяет обмениваться
случаями между машинами без сервера: «Скачать .js» в конструкторе,
«Импорт случая (.js)» на витрине или «Импорт» в конструкторе.

Созданный случай появляется на витрине в пронумерованном списке с меткой
«свой случай», запускается по номеру наряду со встроенными — так же достаётся
«случайным пациентом» — и доступен по прямой ссылке `priem.html?char=<id>`.
В методичке и журнале он полноценный участник: преподаватель принимает коды
студентов по любым случаям.

# Пошаговый осмотр (ветка `guided`)

| Этап | Что делает пользователь |
|---|---|
| 1. Жалобы | слушает вступительную реплику пациента |
| 2. Анамнез | задаёт до 10 вопросов кнопками, каждый ответ озвучен |
| 3. Аускультация | 6 полей на схеме грудной клетки, прослушивание, проба с кашлем |
| 4. Зев | видео переключается на осмотр зева |
| 5. Исследования | назначает из 5 доступных, видит результаты |
| 6. Диагноз | выбирает 1 из 6 вариантов |
| 7. Разбор | оценка в % + список пропущенного |

Оценка: `32 % анамнез · 18 % охват точек · 14 % патология · 4 % зев ·
4 % кашель · 8 % исследования · 20 % диагноз`.

URL: `?demo=1`, `?stage=…` (`intake`, `history`, `auscult`, `throat`,
`workup`, `dx`, `debrief`), `?dx=…`.

## Клиника случая (пример: Абенов, бронхоэктазы)

У каждого персонажа своя ловушка: Есжанова уверена, что «простыла», Омаров
приходит «за ципрофлоксацином от бронхита», Байжанов просит «таблетки от
кашля» при декомпенсации сердечной недостаточности. Ниже — разбор первого
случая.

Ловушка: пациент открывает приём словами «у меня появился небольшой кашель»,
хотя кашлю больше восьми месяцев и мокроты около 100 мл в сутки, в детстве —
тяжёлая пневмония, дважды кровохарканье, не курит. Без расспроса случай
выглядит как ОРВИ.

Аускультация «вид со спины»: **правое лёгкое пациента — слева от вас**.
Хрипы в трёх полях: R-середина, R-низ, L-низ.

Ключевые находки, которые обязан добыть врач: продуктивный кашель большого
объёма с гнойной мокротой · пневмония в детстве как причина · кровохарканье ·
некурящий (значит, не ХОБЛ) · влажные хрипы в базальных отделах и правой
средней доле · пальцы Гиппократа · на КТ отношение диаметра бронха к артерии
больше 1.

## Как добавить свой случай

Проще всего — **конструктором** (вкладка «Конструктор» в `teacher.html`):
он редактирует случай как форму, сохраняет его в виде «своего случая»
(в `localStorage`) и экспортирует/importирует тот же файл `.js`
в размеченном формате (см. подробно `site/characters/README.md`).

Подробная инструкция для пути «по коду» — схема файла случая — тоже в
`site/characters/README.md`. Коротко:

1. Скопируйте любой файл из `site/characters/` (эталон —
   `bronchiectasis-abenov.js`), поменяйте данные; `id` = имя файла без `.js`.
2. Добавьте строку в `site/characters/manifest.js`.
3. Озвучьте ответы: функция `voice_<id>()` в `tools/make-voice.sh` с текстами
   из полей `text:`, затем `bash tools/make-voice.sh <id>`. Имена файлов
   должны совпадать с полями `audio` — иначе пациент промолчит.
4. Звуки лёгких берите из `site/media/lungs/`; новая запись — строка в
   `tools/make-lungs.sh` + перезапуск `tools/make-waveforms.py`.
5. Добавьте пары в `tools/test-nlu.html` и прогоните таблицу: новые основы
   почти всегда сталкиваются с уже существующими.

Координаты точек аускультации (`x`, `y` в файле случая) заданы в системе
координат SVG `viewBox="0 0 300 380"` из `priem.html` — при правке схемы
их нужно править вместе с ней (копия схемы живёт в `<template>` внутри
`teacher.html`, её правят синхронно).

## Откуда взялись медиафайлы

Исходники лежат в `sources/`: два видео Hailuo и четыре реальные записи
лёгких (таблица соответствия — в `sources/README.md`).

**Видео.** Обработаны ffmpeg:

* `patient-idle.mp4` — кроп убирает водяной знак MINIMAX/Hailuo (обрезка
  правого края), затем «палиндром» (`split` → `reverse` → `concat`), чтобы
  цикл шёл без рывка на стыке.
* `patient-throat.mp4` — снят только чёрный паддинг по бокам; исходник сам
  наезжает на ротоглотку во второй половине клипа.
* Видео пока одно на всех: и Есжанова (24, женщина), и Байжанов (67) видят
  того же 34-летнего пациента. Персональные видео — отдельная задача.

**Голос.** `tools/make-voice.sh`: edge-tts, нейронные голоса Microsoft
(бесплатно, без ключей): Дмитрий для мужчин (тон выше для 21-летнего
Омарова, ниже и медленнее для 67-летнего Байжанова), Светлана для
Есжановой. Каталог на персонажа: `site/media/voice/<id>/`. Сеть нужна
только на время генерации — mp3 лежат в репозитории, сайт в рантайме офлайн.
После синтеза — полосовая фильтрация, паузы и `loudnorm`, чтобы громкость
реплик совпадала с аудио аускультации. Раньше здесь был macOS `say`
с единственным русским голосом — женской `Milena`, сдвинутой в мужской
диапазон (`asetrate=44100*0.84` + `atempo=1.190476`).

**Звуки лёгких — важное уточнение:**

* `site/media/lungs/crackles-*.mp3` и `wheeze-asthma.mp3` — **реальные
  записи** из `sources/`, только нормализованы по громкости
  (`tools/make-lungs.sh`).
* `site/media/lungs/normal.mp3` — **синтезирована**: розовый шум →
  `bandpass` → огибающая дыхания через `volume=...:eval=frame`. Записи
  нормального дыхания среди исходников не было, а без «нормы» тренажёр
  теряет главное: задачу отличить патологию от нормы на слух. Как эталон
  везикулярного дыхания для обучения её использовать нельзя.

**Проба с кашлем** тоже честная в своих ограничениях: записи «после
покашливания» не существует, поэтому действие не подделывает изменившийся
звук — оно добавляет клиническую заметку об изменчивости хрипов и
воспроизводит ту же запись.

**Волновая форма.** Web Audio API на `file://` не может анализировать
локальный файл (`createMediaElementSource` отдаёт нули), поэтому пики
считаются заранее в `tools/make-waveforms.py` (RMS, 420 столбиков) и
кладутся в `waveforms.js` рядом с `.json` — `<script>` работает там, где
`fetch()` запрещён.

## Ограничения

Это учебный тренажёр, не медицинское изделие и не диагностический
инструмент. Данные пациентов вымышлены, `lungs/normal.mp3` синтетический.
Сопоставитель свободного текста понимает только те формулировки, основы
которых заложены в файл случая: он проверяет знание терминов и порядка
действий, а не владение языком.
