# Персонажи

Один файл — один персонаж — один законченный клинический случай.
Студенту при загрузке страницы достаётся **случайный** персонаж из
`manifest.js` (отладка: `?char=<имя-файла-без-.js>`, например
`priem.html?char=cf-omarov`).

## Как это работает

1. `priem.html` подключает `manifest.js` и `loader.js` (обычные
   `<script>`, без модулей и fetch — сайт работает с `file://`).
2. `loader.js` выбирает запись манифеста, кладёт её в
   `window.CURRENT_CHARACTER`, подключает файл персонажа и только затем
   `app.js`. Приложение всегда видит ровно один случай в `window.CASES`.

## Как добавить персонажа

Два пути. Проще — **конструктором** (`teacher.html` → «Конструктор»): случай
правится как форма, хранится в `localStorage` на этом браузере и экспортируется/
импортируется файлом с маркерами (формат ниже). Путь «по коду» — так же,
как встроенные персонажи:

1. **Файл случая** — скопируйте любой существующий (эталон по полноте —
   `bronchiectasis-abenov.js`) в `site/characters/<болезнь>-<фамилия>.js`
   и перепишите содержимое. `id` внутри файла = имя файла без `.js`.
2. **Строка в `manifest.js`** — `{ file, disease, label }`.
3. **Каталог озвучки** `site/media/voice/<id>/` — добавьте функцию
   `voice_<id>()` в `tools/make-voice.sh` (тексты копируются дословно из
   полей `text:` файла случая; голос/темп/тон — под возраст и пол) и
   запустите `bash tools/make-voice.sh <id>`. Имена mp3 обязаны совпадать
   со стемами в полях `audio:`.
4. **Звуки лёгких** — берите из общей библиотеки `site/media/lungs/`
   (см. ниже). Если нужна новая запись: положите исходник в `sources/`,
   добавьте строку в `tools/make-lungs.sh`, запустите его, затем
   `python3 tools/make-waveforms.py` — ключ осциллограммы появится в
   `site/media/waveforms.js`.
5. Проверка: `node --check site/characters/<id>.js` и открыть
   `priem.html?char=<id>`. Новый персонаж сам появится в методичке
   (`teacher.html`) и в журнале преподавателя — там отдельные данных нет.

## Свои случаи (конструктор) и формат экспорта

`custom-cases.js` складывает черновики в `localStorage` под ключом
`vp.custom.cases.v1`. Идентификатор присваивается при первом сохранении
(`custom-<slug>`), и случай запускается как обычный:
`priem.html?char=custom-<slug>`.

Экспорт — текстовый файл с маркерами (импорт понимает и голый JSON,
перекинутый текстом):

```
/* комментарий о формате */
// >>> VP-CUSTOM-CASE-V1 >>>
window.__CUSTOM_CASE__ =
{ ...JSON случая... }
;
// <<< VP-CUSTOM-CASE-V1 <<<
```

JSON можно править руками, главное — не трогать сами маркеры. Помогает
обмениваться случаями между компьютерами без сервера.

Минимальный случай допустим без аускультации (`auscultation.enabled = false`
или пустые точки), без паспорта/показателей/назначений: разбор собирается
только по заполненным коллекциям, и их веса перераспределяются между активными
плитками. Всё, что щадит тренажёр, — то, что в случае есть.

## Схема файла (window.CASES.push({...}))

| Секция | Что содержит |
|---|---|
| `id, disease, title` | идентификатор (= имя файла), болезнь, заголовок задания |
| `patient` | `name/short/reason`, видео, `greeting` (реплика-ловушка), `chip` |
| `system` | служебные реплики: `unknown`, `deep`, `cough`, `mouth` |
| `passport` | паспортно-социальная часть (`cat:'ask'`) |
| `vitals` | измеримые показатели (`cat:'measure'`) |
| `questions` | расспрос (`cat:'ask'`), у реплик `audio`+`text`, у находок `tag` |
| `exams` | физикальный осмотр (`cat:'exam'`), `kind:'auscult'|'throat'` |
| `auscultation` | 6 точек + словарь `findings` |
| `orders` | обследования (`cat:'order'`), `role: need/useful/waste` |
| `treatment` | лечение (`cat:'treat'`), `role: need/useful/harm` |
| `diagnosis` | `correct` + `options[]` (`cat:'dx'`), у каждой `verdict`+`why` |
| `algorithm` | правила порядка действий `{id,text,why,when(t),test(t)}` |
| `debrief` | `keyFindings`, `trap`, `nextSteps` |

`patient.chip` — массив `{done: '<id действия>', text: '<жалоба>'}`:
первое сработавшее условие определяет текст чипа в шапке; пока ни одно
не выполнено — «Жалоба не уточнена».

### Распознавание (поля need / no / w)

- `need` — массив групп корней; должны совпасть **все группы**, группа
  закрывается **любым** своим корнем. Корень из 4+ символов ищется как
  подстрока, из 1–3 — как отдельное слово.
- `no` — блокирующие корни (совпал — намерение отвергается).
- `w` — специфичность для разрешения конфликтов (больше = специфичнее).
- Букву «ё» в корнях не используйте: пишите «отек», «солен».
- Категория действия (кнопка/глагол) фильтрует кандидатов **до**
  скоринга, поэтому одинаковые корни в разных категориях не конфликтуют;
  следить надо только за пересечениями внутри одной категории одного
  персонажа.

### Обязательные id (app.js обращается к ним напрямую)

- `p.name`, `p.age` — паспорт;
- `v.temp`, `v.hr`, `v.rr`, `v.spo2`, `v.bp`, `v.bmi` — показатели,
  их `need`-корни должны соответствовать подкнопкам «Измерить»
  (копируйте из существующего файла, не сочиняйте заново);
- `e.ausc` (kind `auscult`), `e.deep` — аускультация и глубокое дыхание.

### Роли и вес

`role` определяет разбор: `need` — обязательное, `useful` — уместное,
`waste` — лишнее (обследования), `harm` — вредное (лечение).
`weight` — вклад в оценку; `important: true` + `why` помечают ключевые
находки для дебрифинга.

## Библиотека звуков лёгких (site/media/lungs/)

| Файл | wf-ключ | Что слышно |
|---|---|---|
| `normal.mp3` | `normal` | везикулярное дыхание |
| `crackles-bronchiectasis.mp3` | `crackles-bronchiectasis` | влажные хрипы, бронхоэктазы (взрослый) |
| `crackles-cf.mp3` | `crackles-cf` | хрипы при муковисцидозе |
| `crackles-edema.mp3` | `crackles-edema` | мелкопузырчатые хрипы, застой/отёк |
| `wheeze-asthma.mp3` | `wheeze-asthma` | свистящие хрипы |

В `auscultation.findings.<имя>` указываются `audio` (путь к mp3) и `wf`
(ключ осциллограммы из `media/waveforms.js`). Видео горла и «ожидания»
пока общие для всех: `media/patient-throat.mp4`, `media/patient-idle.mp4`.
