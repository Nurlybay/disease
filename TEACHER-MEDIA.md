# Генерация учебных изображений и анимаций

Преподаватель → Конструктор случаев → **Создать анимацию**.

1. Написать описание находки или выбрать пример «Сухая кожа кисти» / «Покраснение горла».
2. Создать изображение. Проверить анатомию и соответствие сценарию.
3. При желании отметить проверку, описать движение и создать шестисекундное видео.
4. Проверить готовый материал, выбрать существующий осмотр либо назвать новый.
5. Прикрепить материал, уточнить текст результата/критерии и **сохранить случай**. Для группы — опубликовать его обычной кнопкой конструктора.

Студент получает материал только после соответствующего действия осмотра. Видео включается вручную, по умолчанию без звука; исходное изображение доступно отдельно. Материалы помечены как синтетические. Для нового осмотра критерии патологии не назначаются автоматически: их определяет преподаватель.

## Подключение администратора

Нужны Supabase CLI с доступом к проекту, подтверждённый аккаунт с `app_metadata.role = teacher` или `admin`, ключ OpenRouter с доступом к `openai/gpt-image-2.5-sunburst` и `minimax/hailuo-3-max`.

1. Применить миграцию `supabase/migrations/202609100002_teacher_media.sql` через миграции Supabase. Она добавляет таблицу заданий, атомарные лимиты и bucket `teaching-media`.
2. В Supabase Dashboard → Edge Functions → Secrets проверить наличие `OPENROUTER_API_KEY` (используется существующий ключ проекта). В браузер, git и чат ключи не вставлять. `SUPABASE_URL`, `SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY` доступны в размещённых Edge Functions автоматически.
3. При необходимости задать `MEDIA_USER_DAILY_LIMIT` (по умолчанию 20) и `MEDIA_GLOBAL_DAILY_LIMIT` (100). Считаются все новые запросы за последние 24 часа, включая неудачные; это лимит количества, а не денежный лимит. Денежные ограничения задаются дополнительно у провайдеров.
4. Собрать защищённые скрипты и клиент авторизации:

   ```sh
   python3 tools/build-learning-content.py
   npm --prefix tools/auth-build run build
   ```

5. Развернуть `teacher-media` и обновлённый `learning-content`:

   ```sh
   supabase functions deploy teacher-media
   supabase functions deploy learning-content
   python3 tools/build-public-site.py
   ```

6. Опубликовать `.public-site` обычным способом проекта. Обновлять страницу преподавателя вместе с серверными функциями, чтобы загрузился новый `mediaRequest`.

Без ключа библиотека и существующие файлы доступны, кнопки неподключённого вида генерации отключены. Без развёрнутой функции интерфейс сообщает о недоступности сервиса.

## Архитектура и хранение

- `site/media-studio.js`: форма, библиотека последних 50 заданий текущего преподавателя, статус с интервалом 30 секунд; опрос приостанавливается в скрытой вкладке или закрытом разделе.
- `site/learning-access.js`: запросы с актуальной Supabase-сессией через существующий AuthClient.
- `teacher-media`: проверяет подтверждённого пользователя и роль из доверенного `app_metadata` для каждой операции. Браузер не может выбрать чужое задание, модель или произвольный URL для скачивания.
- Изображение: OpenRouter `POST /api/v1/images`, `openai/gpt-image-2.5-sunburst`, medium, 16:9, PNG.
- Видео: OpenRouter `POST /api/v1/videos`, `minimax/hailuo-3-max`, 6 секунд, 768p, 16:9, без звука; исходное изображение — первый кадр. Запросы независимы: создание картинки не запускает платное видео автоматически.
- Новое задание получает UUID. Повтор с тем же UUID не вызывает повторную генерацию. Резервирование и лимиты сериализуются транзакционной блокировкой в Postgres.
- Создание изображения и видеозадания OpenRouter выполняются через `EdgeRuntime.waitUntil`. Хостинг должен поддерживать фоновые задачи и достаточное время выполнения (до 120 секунд для картинки плюс запись). Прерывание не вызывает автоматическую платную повторную попытку.
- Статус видео запрашивается при открытой студии. Завершившийся файл копируется в Supabase Storage при проверке статуса. Если страницу закрыли, нужно вернуться и выбрать задание; тогда загрузка продолжится. Это не автономная очередь с круглосуточным worker.
- При сбое скачивания/хранилища остаётся ID задачи OpenRouter: обновление повторяет скачивание, не генерацию. При неизвестном исходе отправки появляется статус `uncertain`; администратор сверяет запрос с кабинетом провайдера перед новой платной попыткой.
- `usage` сохраняется на сервере для полученных ответов провайдеров. Интерфейс не обещает фиксированную стоимость и не выдаёт расчёт за фактическое списание.
- Bucket **публичный**, предназначен только для синтетических учебных материалов. Реальные фотографии пациентов здесь не загружаются. Временные ссылки провайдера не сохраняются в случаях: используются постоянные URL нашего Storage. Оригиналы/видео остаются в облаке; экспорт `.js` содержит ссылки, поэтому офлайн-видео этим экспортом не обеспечивается.
- Автоматическое удаление из библиотеки не реализовано: оно могло бы сломать ссылки опубликованных случаев. Удаление объектов выполняется администратором после проверки ссылок.
- Видео скачивается только через фиксированный авторизованный endpoint OpenRouter `/api/v1/videos/{id}/content?index=0`. Произвольные ссылки из ответов и браузера игнорируются; перенаправления запрещены.

## Проверка

```sh
node tools/test-teacher-media.js
node tools/test-patient-video.js
node tools/test-learning-access.js
```

Тесты используют подменённые ответы провайдеров и не расходуют средства. После развёртывания необходим один живой проход под преподавателем: картинка → видео → прикрепление → сохранение → просмотр студентом. Фактические доступ к модели, качество медицинского изображения, время и списание подтверждаются только этим проходом.

Документация API:
- https://openrouter.ai/docs/guides/overview/multimodal/image-generation
- https://openrouter.ai/docs/guides/overview/multimodal/video-generation
- https://openrouter.ai/api/v1/videos/models

## Пациенты и сцены (второй выпуск)

Применить также `202609100003_media_scenes.sql` перед обновлением функции.

- В студии доступны три режима: находка, внешность пациента, сцена с выбранным пациентом. Для сцены преподаватель выбирает свои сохранённые изображения; находка необязательна. Кнопка «Использовать как внешность пациента» переносит выбранное изображение и необязательное видео в черновик. После этого сохранить случай.
- Сцена генерируется с изображением пациента и необязательным образцом находки как references. Это не гарантирует совпадение внешности или медицинских деталей: преподаватель проверяет результат. Крупный план берётся из выбранного образца находки, поэтому совместимость с пациентом проверяется отдельно.
- Материал прикрепляется к существующему/новому вопросу или осмотру. Для нового вопроса нужно заполнить текст ответа и корни распознавания в конструкторе; текст ответа автоматически не сочиняется.
- В приёме сцена появляется в ответе на соответствующий вопрос/осмотр. Кнопка «Открыть сцену крупно» открывает диалог: видео → выбранный крупный план → возврат к пациенту. Крупный план можно открыть до конца видео. Это составной просмотр, не непрерывный сгенерированный переход камеры.
- Ярлык «Есть анимация / Без анимации» показан на витрине, в списке методички и в конструкторе. Учитываются видео пациента и вопросы/осмотры. В старых мужских случаях учитывается стандартное видео пациента. Само наличие фотографии не считается анимацией.
- Стоимость выбранного задания и сумма известных `usage.cost` последних 50 загруженных заданий показаны в студии; это не полный баланс аккаунта и не комиссия пополнения.
- Изменение клинической формулировки вопроса требует соответствующей привязки `need` (как и раньше). Сцены не выбираются языковой моделью произвольно по похожим жалобам.
