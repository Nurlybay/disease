# Необязательная анимация жалобы

Преподаватель → Конструктор случаев → «Добавить анимацию жалобы».

1. Выбрать готового пациента. Этот же выбор доступен в обычном разделе «Случай», без открытия медиастудии. В каталоге доступны девять существующих персонажей с фотографиями. Создание новых персонажей отключено в интерфейсе и API.
2. Написать, что пациент показывает, либо выбрать подсказку. При необходимости открыть дополнительные настройки: выбрать собственный образец находки и уточнить движение.
3. Подготовить кадр, проверить внешность и анатомию, затем создать шестисекундную анимацию.
4. Просмотреть видео, отметить соответствие жалобе и нажать «Использовать при рассказе о жалобах».
5. Сохранить случай обычной кнопкой конструктора. Публикация для группы — существующей кнопкой публикации.

Можно закрыть необязательный шаг или нажать «Продолжить без создания анимации». Это не удаляет ранее добавленный материал. Для удаления есть кнопка «Убрать анимацию жалобы» в случае. Из библиотеки можно повторно использовать готовый материал без генерации.

## Показ студенту

`complaintMedia` хранится на уровне случая. Тренажёр распознаёт шаблоны общих вопросов о текущих жалобах: «Что вас беспокоит?», «Какие у вас жалобы?», «С чем вы пришли?» и соответствующие базовые английские/казахские формулировки. Анимация появляется в ответе и запускается, только если в случае есть видео. Просьбы «Покажите руки», «Покажите горло» и другие поддерживаемые области сопоставляются с сохранённым описанием сцены. Для старых материалов без описания используется повод обращения; повторный выбор видео в библиотеке сохраняет описание. Просьба показать другую область не запускает неподходящую сцену. Она работает и с ответом ИИ, и с шаблонным расспросом. Дополнительных платных запросов для выбора сцены нет. Это набор шаблонов, а не свободная семантическая классификация.

Вопросы о лекарствах, прошлом анамнезе и другие неподходящие реплики не получают эту анимацию. Автопоказ не отмечает пункты оценки. Если в авторском случае нет подходящего шаблонного ответа, общий вопрос о жалобах с имеющейся анимацией получает текст повода обращения. При подходящей реплике видео автоматически открывается и воспроизводится без звука; крупный просмотр показывает видео и затем выбранный образец находки. Соответствие крупного плана пациенту проверяет преподаватель.

Старые вложения отдельных вопросов/осмотров сохраняются для совместимости. Новая студия не требует такой привязки. При смене готового персонажа анимация жалобы снимается с черновика, чтобы не показать другого человека. Сам файл остаётся в библиотеке. Сцена, содержащая идентификатор персонажа, не прикрепляется к другому персонажу.

## Хранение и стоимость

- Существующий серверный `OPENROUTER_API_KEY` используется для изображения `openai/gpt-image-2.5-sunburst` (medium, 16:9, PNG) и видео `minimax/hailuo-3-max` (6 секунд, 768p, без звука).
- Сервер принимает идентификатор готового персонажа из фиксированного списка, а не URL браузера. Дополнительная находка выбирается только из заданий этого преподавателя. Роли teacher/admin проверяются по доверенному app_metadata.
- `teacher_media_jobs.context` сохраняет тип материала, исходные ссылки и идентификатор пациента. Библиотека показывает последние 50 заданий и сумму известных `usage.cost`; это не полный баланс OpenRouter и не комиссия пополнения.
- Запросы идемпотентны по UUID. Атомарные дневные лимиты: 20 заданий на пользователя и 100 на проект, переопределяются `MEDIA_USER_DAILY_LIMIT` / `MEDIA_GLOBAL_DAILY_LIMIT`. Это ограничения количества, не суммы.
- При неизвестном исходе запроса нет автоматической платной повторной попытки. При сбое скачивания готового видео повторяется только скачивание.
- Файлы хранятся в публичном bucket `teaching-media`, только для синтетических учебных материалов. Экспорт случая сохраняет ссылки; нужен интернет. Старые файлы автоматически не удаляются.
- Видео финализируется при проверке статуса открытой студией (30 секунд). После закрытия страницы нужно вернуться к заданию. Это не автономный worker.
- Крупный план — выбранное изображение находки, а не гарантированно согласованный с пациентом результат. Генерация по фотографии не гарантирует идентичность; результат требует просмотра.

## Развёртывание и проверка

Применить миграции `202609100002_teacher_media.sql` и `202609100003_media_scenes.sql`. Собрать пакет через `python3 tools/build-learning-content.py`, развернуть `teacher-media` и `learning-content`, опубликовать публичный сайт (`python3 tools/build-public-site.py`). Новые поля случая живут в экспортируемом JSON и не требуют дополнительной миграции.

Проверки: `node tools/test-teacher-media.js`, `node tools/test-learning-access.js`, `node tools/test-patient-video.js`, `node tools/test-practice.js`. Тесты не расходуют средства. Они проверяют права, запрет создания персонажа, безопасный выбор references, идемпотентность, расходы, сохранение случая и показ анимации в реальном обработчике протокола для подходящих/неподходящих вопросов.
